# Coffeella Café — المنيو وCMS

موقع عربي RTL لمنيو كوفيلا كافيه. يعمل الموقع كواجهة ثابتة افتراضياً، ويمكن ربطه تدريجياً بقاعدة بيانات Supabase.

## الملفات الأساسية

| الملف | الوظيفة |
| --- | --- |
| `index.html` | واجهة المنيو العامة |
| `styles.css` | تصميم الواجهة ومتغيرات الألوان |
| `app.js` | عرض المنيو والبحث والتنقل |
| `menu-data.js` | بيانات المنيو الاحتياطية الحالية |
| `cms-config.js` | إعدادات Supabase العامة (رابط المشروع ومفتاح publishable/anon فقط) |
| `cms-client.js` | القراءة من قاعدة البيانات وإرسال أحداث التحليلات |
| `bootstrap.js` | تحميل المنيو والإعدادات المنشورة قبل بناء الواجهة |
| `analytics.js` | أحداث مشاهدة الصفحات وضغطات الأزرار |
| `admin.html` | لوحة تحكم أولية محمية بتسجيل الدخول |
| `supabase/migrations/` | مخطط الجداول وسياسات RLS وتخزين الوسائط |

## تشغيل الموقع الثابت

يمكن فتح الملفات أو نشرها على استضافة ثابتة كما كان سابقاً. إذا لم تضبط إعدادات Supabase أو لم توجد بيانات منشورة، يستخدم الموقع بيانات `menu-data.js` الحالية.

## تفعيل Supabase

1. أنشئ مشروعاً في [Supabase](https://supabase.com/).
2. افتح SQL Editor وشغّل ملف `supabase/migrations/202610220001_initial_cms.sql`.
3. من إعدادات المشروع انسخ Project URL ومفتاح publishable/anon إلى `cms-config.js`.
4. لا تضع مفتاح `service_role` أو أي سر إداري في ملفات المتصفح أو المستودع.
5. أنشئ حساب المالك الأول من Authentication في Supabase، ثم شغّل الاستعلام التالي في SQL Editor مع استبدال البريد بعنوان الحساب الذي أنشأته:

```sql
insert into public.site_members (user_id, role, status)
select id, 'owner', 'active'
from auth.users
where email = 'owner@example.com'
on conflict (user_id) do update set role = 'owner', status = 'active';
```

6. افتح `/admin.html` وسجّل الدخول بالحساب نفسه.
7. افتح تبويب «الأصناف والأسعار» في لوحة التحكم واضغط «استيراد المنيو الحالي». سيُستورد محتوى `menu-data.js` إلى `menu_categories`, `menu_groups`, و`menu_items` باستخدام مفاتيح ثابتة، ويمكن إعادة تشغيل الاستيراد لتحديث المحتوى من دون حذف الأصناف الموجودة.

## الموجود في هذه المرحلة

- مخطط قاعدة بيانات أولي للعضويات والأدوار، والصفحات، وإعدادات التصميم، والأقسام والأصناف، وقواعد رفع الملفات، وأحداث التحليلات.
- سياسات Row Level Security للجداول ومساحة تخزين الصور.
- تحميل اختياري للمنيو المنشور والإعدادات من Supabase، مع fallback إلى المنيو الحالي.
- تسجيل مشاهدات الصفحات، ومدد المغادرة المسجلة، ونقرات العناصر الموسومة.
- لوحة تحكم أولية لتسجيل الدخول، وملخص تحليلات، واستيراد/تحديث المنيو الحالي، وتعديل بعض حقول الأصناف والألوان.

## ما لم يكتمل بعد

هذه **مرحلة تأسيس وليست CMS كاملاً بعد**. ما زال مطلوباً تنفيذ واستكمال: محرر صفحات مرئي بالسحب والإفلات، CRUD كامل للصفحات والأزرار والبطاقات والأيقونات، رفع وإدارة الوسائط وقواعدها من الواجهة، إدارة المشرفين والحظر ونقل الملكية عبر إجراءات خادمية محمية، سجل تدقيق، تقارير تحليلية أدق، واختبارات أمنية وتشغيلية.

قياس مدة البقاء يعتمد على وصول أحداث المغادرة؛ قد لا تتوفر مدة دقيقة عند إغلاق المتصفح أو فقدان الاتصال. كما أن الأحداث الحالية تسجل معرّفات العناصر المعروفة أو وصفاً موجزاً للزر، ولا تجمع محتويات النماذج أو كلمات المرور.

## ملاحظات أمنية

- مفتاح Supabase العام ليس بديلاً عن سياسات RLS.
- لا تمنح صلاحيات المالك من الواجهة العامة. التعيين الأول للمالك يتم من SQL Editor بعد إنشاء حسابه.
- لا تستخدم خدمة `service_role` في المتصفح.
- قبل استخدام الموقع على بيانات حقيقية، راجع سياسات RLS، وإعدادات التسجيل في Supabase، وحدود الرفع، والخصوصية والاحتفاظ بأحداث التحليلات.
